# /polish — 文章・仕様・出力内容の整形、改善

| 項目 | 内容 |
| --- | --- |
| 正準名 | `/polish` |
| エイリアス | `/curren-polish`（過去互換。受理時に正準名へ正規化し、表記は `command_alias` に保持） |
| 想定 task_type | `portfolio` / `document` / `coding` ほか |

## 役割

既存の成果物の**内容の意味を変えずに**、構成・表現・読みやすさ・体裁を改善する。
新規作成や仕様の決定は行わない（仕様化は `/spec` の責務）。

## 入力

- 整形対象（ファイルパスまたは先行タスクの `result`）
- 整形方針（任意。例:「トーンは維持、構成のみ改善」「範囲外: 技術的内容の書き換え」）

## 出力パケットの要件

- `command`: `/polish`
- `status`: `done` / `need_review`（複数案があり人間の選択が必要な場合）
- `result.path` または `result.url`: 整形後の成果物（元ファイルを直接上書きしない場合は差分も示す）
- `requirement_summary`: 何を範囲とし、何を範囲外としたか
- 複数案を出した場合は `actions` に比較用リンクを含める

## ハンドオフでの利用

`/review` の指摘を受けて修正する後工程、または `/spec` の前段の文章整備として使う。
